# Developing KaTrain

KaTrain is a [Tauri v2](https://v2.tauri.app/) desktop app: a React + TypeScript frontend with all of the go logic,
and a small Rust backend that runs KataGo. It started as a port of the original Python + Kivy KaTrain
([sanderland/katrain](https://github.com/sanderland/katrain)); the core logic was ported module by module and is tested
against data generated by the Python code, so the two behave the same and read and write the same SGF files.

## Layout

```
src/core/        Game logic with no UI or Tauri dependencies
  move.ts          moves and coordinates
  sgf.ts           SGF / NGF / GIB parsing, SGF writing
  gameNode.ts      game tree node + analysis bookkeeping (candidate moves, point loss, KT analysis cache)
  game.ts          board state and capture rules, navigation, analysis requests, extra analysis modes,
                   insert mode, self-play, region of interest
  engine.ts        KataGo analysis-engine client: query ids, priorities, pondering, result dispatch,
                   reconnecting to a remote engine
  ai.ts            AI strategies and rank estimation
  report.ts        player performance report
  tsumego.ts       tsumego frame
  models.ts        downloadable KataGo models
  i18n.ts          gettext lookup + Python-style format strings
src/state/       zustand store with the controller logic (AI turns, teaching, timer, pondering, files),
                 the user config (defaults.json holds the defaults) and the platform layer (Tauri or browser)
src/ui/          React components (SVG board, move tree, graph, panels, dialogs)
src/i18n/        translations (gettext .po files, one per language)
src/assets/      sounds
src-tauri/       Rust backend: runs KataGo (local process, custom command, or a WebSocket to a remote engine)
                 and streams its output as events; reads/writes files with encoding detection; stores the
                 config; downloads models
resources/       bundled KataGo binaries (Windows, Linux; macOS is built by scripts/build-katago-macos.sh),
                 the default model and the KataGo config
tests-ts/        unit tests (vitest), golden data generated from the Python implementation, test games
```

The Rust side deliberately knows nothing about go: it only owns the engine connection. KataGo's analysis engine
speaks JSON lines over stdin/stdout (or over a WebSocket for a remote engine), so the TypeScript `KataGoEngine`
talks to it through a small `EngineTransport` interface. The desktop app uses the Tauri transport; the tests use a
`child_process` transport, and `scripts/engine-bridge.mjs` provides one for working on the UI in a normal browser.

Paths in the config such as `katrain/models/...` refer to the bundled resources, as in the Python version, so
existing configs keep working.

## Commands

Prerequisites: Node 20+, Rust (stable), and the [Tauri system dependencies](https://v2.tauri.app/start/prerequisites/)
(on Debian/Ubuntu: `libwebkit2gtk-4.1-dev libgtk-3-dev librsvg2-dev libxdo-dev libssl-dev`).

```sh
npm install
npm run tauri dev        # desktop app with hot reload
npm run tauri build      # installers in src-tauri/target/release/bundle
npm test                 # unit tests
npm run typecheck
cargo test --manifest-path src-tauri/Cargo.toml
```

KataGo is bundled for Windows and Linux (`resources/KataGo`). For macOS, `scripts/build-katago-macos.sh` builds it
from source (Metal on Apple Silicon, OpenCL on Intel) with its Homebrew libraries copied next to it, as CI does;
run it once before `npm run tauri build` or `npm run tauri dev` on a Mac. Without a bundled KataGo the app falls
back to one on `PATH` or in Homebrew's folders (`brew install katago`).

On Linux the bundled `resources/KataGo/katago` is KataGo's own AppImage, so it needs FUSE (`libfuse2`). The packages
install it in `usr/share/KaTrain` rather than with the other resources in `usr/lib/KaTrain`, because linuxdeploy (used
to build KaTrain's AppImage) rewrites every ELF file below `usr/lib`, which corrupts it: it then crashes on start.
Programs started from inside KaTrain's AppImage must also not inherit the environment it sets up for itself
(`src-tauri/src/appimage.rs`).

The AppImage bundles the GStreamer plugins of the build machine (`bundleMediaFramework`), so building it needs
`gstreamer1.0-plugins-base gstreamer1.0-plugins-good gstreamer1.0-alsa gstreamer1.0-pulseaudio`. Without them, the web
view crashes the first time the app plays a sound.

WebKitGTK's `<audio>` cannot load the app's own URLs, so `src/ui/sounds.ts` falls back to Web Audio there, with a new
`AudioContext` for each sound. To test it, count the sounds at the output with `parec` on the sink's `.monitor` while
two AIs play, and include a Bluetooth output: with one shared context, it only plays the first sound.

UI work in a browser (no Tauri), with a real engine:

```sh
npm run dev
node scripts/engine-bridge.mjs     # runs KataGo on 127.0.0.1:8765 and prints the URL to open (with a token)
```

End-to-end tests drive the real bundled KataGo from the TypeScript core:

```sh
KATAGO_E2E=1 npx vitest run tests-ts/engine.e2e.test.ts tests-ts/selfplay.e2e.test.ts
# include the human-like AIs:
KATAGO_E2E=1 KATAGO_HUMAN_MODEL=/path/to/b18c384nbt-humanv0.bin.gz npx vitest run tests-ts/engine.e2e.test.ts
```

Downloaded models are stored in the app data folder (`models/`); on macOS that is
`~/Library/Application Support/io.github.yongjer.katrain/models`. Models in the Python version's `~/.katrain`
folder are offered as well.

## Translations

Translations are the gettext files in `src/i18n`. To improve one, edit the `msgstr` entries of that language's file.
To add a language, copy `en.po`, translate the `msgstr` entries (leave anything between `{}` as it is), and add the
language to `LANGUAGES` in `src/ui/i18nLoader.ts`.

## Test builds

Every push to `tauri-v2` builds Windows, macOS (Apple Silicon and Intel) and Linux installers in CI and refreshes the
[`tauri-nightly` prerelease](https://github.com/yongjer/katrain/releases/tag/tauri-nightly) with them.
These are unsigned test builds.

## Not ported from the Python version

- Downloading KataGo binaries from the settings (set the path to a KataGo you downloaded instead)
- Contributing to KataGo's distributed training
- Themes and configurable keyboard shortcuts
- The minimalistic UI modes (`~` / `F12`)
